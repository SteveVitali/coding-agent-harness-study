## B. One agent turn, keystroke → persisted state

1. **Input ingestion:** client calls `session.prompt` via SDK; server routes to `SessionPrompt.prompt` (src/session/prompt.ts:1052-1071), which builds the user message via `createUserMessage` (prompt.ts:635-1050): file parts are resolved by *actually executing the read tool* server-side and inlining output as synthetic text parts (prompt.ts:808-906); MCP resources are fetched and attached (prompt.ts:703-783); plugin hook `chat.message` may mutate parts (prompt.ts:999-1009). Message + parts persisted immediately (`sessions.updateMessage/updatePart`, prompt.ts:1046-1047).
2. **Loop:** `runLoop` is an explicit `while (true)` (prompt.ts:1081-1341), re-entered via `SessionRunState.ensureRunning` (prompt.ts:1343-1347) so concurrent prompts join the running loop. Exit condition: last assistant finish reason not `tool-calls` and no unresolved tool parts (prompt.ts:1111-1130).
3. **Instruction assembly:** `SystemPrompt.environment` (model id, cwd, git-ness, date — src/session/system.ts:60-96) + `Instruction.system()` which loads `AGENTS.md`, `CLAUDE.md` (unless disabled), deprecated `CONTEXT.md`, global `~/.config/opencode/AGENTS.md` and `~/.claude/CLAUDE.md`, plus config `instructions` globs and **remote HTTP(S) instruction URLs** (src/session/instruction.ts:60-169). Base persona prompt is chosen by **model-family substring match**: claude→anthropic.txt, gpt→gpt.txt/codex.txt, gpt-4/o1/o3→beast.txt, gemini→gemini.txt, kimi, trinity, muse-spark→meta.txt, else default.txt (system.ts:27-42). Skills list and MCP server instructions are appended (system.ts:98-128). Nested AGENTS.md are attached lazily when the read tool touches files beneath them (instruction.ts:179-221).
4. **Context selection:** `MessageV2.filterCompactedEffect` drops pre-compaction history at read time (prompt.ts:1092-1094); `SessionReminders.apply` injects synthetic reminders (prompt.ts:1180).
5. **Tool assembly:** `SessionTools.resolve` (src/session/tools.ts:41-493) wraps registry tools as AI-SDK `tool()`s; each execute path runs plugin `tool.execute.before/after` and a `ctx.ask` permission closure bound to agent+session rulesets (tools.ts:59-90). `ToolRegistry.tools` gates by model: GPT-5-family gets `apply_patch` instead of `edit`/`write` (src/tool/registry.ts:292-296).
6. **Request construction/provider abstraction:** `LLM.stream` (src/session/llm.ts:85-355). Default path is AI SDK `streamText` with `wrapLanguageModel` middleware calling `ProviderTransform.message` (llm.ts:325-343); params/headers prepared by `LLMRequestPrep` incl. plugin `chat.params`/`chat.headers`. Experimental native runtime (`@opencode-ai/llm`) behind `flags.experimentalNativeLlm`, with logged fallback (llm.ts:226-269). Providers come from a models.dev catalog (packages/core/src/models-dev.ts:250) plus per-provider bootstrap closures (~40 providers, src/provider/provider.ts); custom providers default to `@ai-sdk/openai-compatible` + `baseURL` (provider.ts:1221).
7. **Streaming → parsing:** both runtimes emit normalized `LLMEvent`s (llm.ts:357-381); `SessionProcessor.handleEvent` folds text/reasoning/tool-input/tool-call/tool-result/step events, persisting deltas as they arrive (`session.updatePartDelta`, src/session/processor.ts:278-537). Malformed tool calls: `experimental_repairToolCall` retries lowercased name, else routes to an `invalid` tool that reports the error to the model (llm.ts:296-312).
8. **Authorization:** `Permission.ask` — wildcard rules `{permission, pattern, action: allow|deny|ask}`, **last match wins, default ask** (src/permission/index.ts:28-38); ask publishes an event and blocks on an in-process `Deferred` until a client replies once/always/reject (index.ts:96-107); "always" appends session-scoped allow rules (index.ts:145-151). Plugin hook `permission.ask` can force allow/deny (packages/plugin/src/index.ts:261). Doom-loop guard: 3 identical consecutive tool calls force an ask (processor.ts:29,356-380).
9. **Execution locus:** host process, no sandbox. Shell: command parsed with **tree-sitter bash/powershell WASM** to derive permission patterns per sub-command (`BashArity.prefix` → `"git status *"`-style always-patterns) and detect file args outside the worktree (`external_directory` ask) (src/tool/shell.ts:257-414); then spawned directly via `ChildProcessSpawner` with default 2-min timeout, abort/timeout race, force-kill after 3s (shell.ts:481-559). Edit: 9 cascading replacers (exact → line-trimmed → block-anchor w/ Levenshtein ≥0.65 → whitespace/indentation/escape-normalized → …) credited to cline and gemini-cli (src/tool/edit.ts:1-4,694-729), diff-preview permission ask before write, formatter + LSP diagnostics feedback after (edit.ts:145-201).
10. **Observation return:** tool output `{title, output, metadata, attachments}`; truncation via `Truncate.output` with spill-to-file path in output ("Full output saved to: …", shell.ts:566-594).
11. **Persistence:** every message/part update hits SQLite immediately; per-step git snapshots produce `patch` parts (processor.ts:424-470); usage/cost per step from models.dev pricing incl. >200K tiering and Copilot nanoAiu billing (src/session/session.ts:338-400).
12. **Compaction:** overflow check each step; compaction is a hidden "compaction" agent generating a summary message, preserving the last ~2 turns within a 2k–8k token budget (src/session/compaction.ts:32-34,188-239); `prune` non-destructively marks old tool outputs `compacted` (protects `skill` outputs) (compaction.ts:28-31,243-287); auto-continue injects a synthetic user "Continue if you have next steps…" (compaction.ts:473-501).
13. **Failure/retry/cancel:** provider-aware retry policy with status events (processor.ts:660-674); cancellation via Effect interrupt → AbortController → cleanup marks orphaned tool parts `interrupted` (processor.ts:539-597); content-filter finishes surfaced as errors (prompt.ts:1295-1317).

## D. Governing philosophy

A **product-first, server-centric IDE-agent platform**: one heavily-engineered engine (Effect services, SQLite, event bus) with every UI — TUI, web, desktop, VS Code, Zed-via-ACP, Slack, GitHub — as a thin client of the same HTTP API. It **owns** enormous complexity on behalf of users: provider quirks (patched AI-SDK forks, per-family prompts/toolsets, cache-point placement, cost tables), fuzzy edit repair, tree-sitter permission inference, compaction/pruning, retry taxonomies, snapshots/reverts. It **pushes onto plugins/users**: safety (no sandbox — permissions are advisory prompts), memory, verification workflows, and cross-agent orchestration. The commercial gradient (console/enterprise/infra packages in-tree) is real but severable: the local engine runs fully standalone.

## E. Hidden tradeoffs

- **Prompt-only permissions** — CONFIRMED: enforcement is in-process rule evaluation + Deferred prompt (permission/index.ts:96-107); nothing OS-level stops an allowed-pattern command from doing anything. Tree-sitter parsing narrows the *ask*, and dynamic constructs (`$(...)`) are flagged, but an allowed `bash` invocation is unconstrained.
- **Undocumented model-family dependence** — CONFIRMED: behavior forks on model-ID substrings for system prompt (system.ts:27-42) and toolset (registry.ts:292-296); a local model named "gpt-…" silently gets codex prompts + apply_patch. Cross-harness benchmark results will partly measure these adaptations, not the model.
- **Leaky provider abstraction** — CONFIRMED: 16 patched dependencies incl. 5 `@ai-sdk/*` providers and the MCP SDK (package.json patchedDependencies); GitLab workflow models bypass the normal tool loop entirely (llm.ts:119-206).
- **Lossy compaction of tool evidence** — CONFIRMED: summarization truncates tool outputs to 2000 chars and strips media (compaction.ts:30,351-354); pruning erases older tool outputs from context (compaction.ts:243-287). Mitigated: DB rows are kept; auto-continue message can cause silent task drift after compaction (compaction.ts:485 injects "Continue if you have next steps…").
- **Unstable plugin surface** — CONFIRMED: key hooks are prefixed `experimental.` and one is documented "not a stable plugin contract and may change" (compaction.ts:491-494).
- **Duplicated client/server state** — RISK: ACP layer keeps its own session/config snapshots (`sessionSnapshots` Map, acp/service.ts:85-92) mirrored from server state; TUI keeps sync stores; divergence bugs are plausible (no direct defect observed).
- **Websearch sends queries to third-party services by default** — CONFIRMED: queries A/B-routed to exa.ai / parallel.ai MCP endpoints keyed on session hash, keyless (websearch.ts:30-37; mcp-websearch.ts:4-7) — gated by provider flags (`webSearchEnabled(input.providerID, ...)`, registry.ts:288-290), so exposure depends on provider.
- **Brittle-parse hedges exist** — CONFIRMED (positive): invalid-tool routing (llm.ts:296-312) and disproportionate-match refusal (edit.ts:731-737) show the failure modes are known and handled.
- **Token overhead** — RISK: per-turn instruction re-attachment (nested AGENTS.md, skill catalogs, MCP instructions in system prompt) plus synthetic parts for every attached file inflate context; mitigated by cache breakpoints but unmeasured here.
- **Cancellation is strong** — CONFIRMED: Effect interrupts propagate to AbortControllers, orphaned tool parts get marked `interrupted` and excluded from loop-continuation logic (processor.ts:539-597; prompt.ts:96-100).
- **Observability** — CONFIRMED: opt-in OpenTelemetry tracing with session.id-tagged spans (llm.ts:208-222,344-352).
- **Core-loop test coverage is real, not thin** — CONFIRMED: dedicated tests for processor, retry, compaction, structured output, prompt (test/session/*).

## H. Portability-adapter inputs

- **Skills=procedure:** native fit — drop SKILL.md under `.opencode/skill/` or Claude-style `skills/**` (skill/index.ts:23-25); loaded via `skill` tool, listed in system prompt.
- **AGENTS.md=policy:** native fit incl. nested/lazy loading and CLAUDE.md compatibility (instruction.ts:60-221).
- **Files=state:** fine; but **native todos (todowrite) and session summaries will shadow file-based state** — disable via permission `{"todowrite": "deny"}`-style rules (Permission.disabled hides denied tools, permission/index.ts:204-214).
- **git=history:** harness makes its own git snapshots in a side git-dir (snapshot/index.ts) — independent of the repo's git; no interference expected, but "checkpoint" semantics duplicate an adapter's git usage.
- **MCP=optional tools:** config `mcp` block; per-tool permission default is ask → set `allow` rules for unattended runs (tools.ts:408).
- **What the harness silently fights:** auto-compaction discarding tool detail mid-task (use `compaction.auto=false` — processor honors it, processor.ts:607-616 — or `preserve_recent_tokens`); auto-continue synthetic prompts steering after compaction (disable via `experimental.compaction.autocontinue` plugin hook); doom-loop asks interrupting legitimate repeated calls under `--auto`? No — `--auto` approves them.
- **Unattended spec→plan→tests→implement→review→verify→PR:** high feasibility — plan agent (edit-denied) → build agent, `opencode run --agent`, permission rulesets, git/PR command, GitHub Action; the missing piece is verification orchestration (tests are just shell) and OS-level containment (bring your own container).

**Strengths:** real client/server architecture with many first-class surfaces; strongest-in-class session model (SQLite, forking, snapshots, revert, background subagents); serious core-loop testing; broad provider matrix with caching/cost accounting; ACP + SDK embeddability; graceful failure handling (invalid tool, retries, cancellation).
**Weaknesses:** no OS-enforced sandbox; heavy hidden model-family conditioning; experimental/unstable plugin hooks; third-party default websearch; complexity (Effect + 33 packages) makes loop modification a fork-level task.
**Best fit:** interactive terminal/IDE development, embedding an agent backend into products, teams wanting one engine behind many UIs.
**Poor fit:** hostile-input or high-assurance environments needing kernel-level containment; research needing a minimal, easily-modified loop; strict-provider-neutral benchmarking without controlling for its per-family adaptations.
